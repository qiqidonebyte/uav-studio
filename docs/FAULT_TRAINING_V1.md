# Fault Training V1 · 装调检修故障实训案例库

## 目标

把现有“系统调试”从自由调试工具升级为可重复的故障诊断实训：

```text
选择案例
  ↓
只给故障现象与任务
  ↓
回到原调试工作台
  ↓
学生自主选择传感器 / RC / 动力 / 安全工具
  ↓
修复
  ↓
重新验证
  ↓
提交诊断
  ↓
过程评分
```

V1 不新增一级“故障检修”页面。案例库位于 `/debugging` 左侧，调试工具仍然是同一套。

## 代码位置

```text

frontend/src/utils/training.ts                 # 运行时类型、计分模型、目录加载
frontend/src/views/Debugging.vue               # 案例库 UI + 故障注入 + 提交闭环

```

案例目录与页面代码分离。新增案例不再需要继续扩大 Vue 中的案例文案。

## V1 故障注入边界

V1 使用“教学注入”优先保证可重复性与安全：

- 罗盘案例：教学传感器状态层注入；
- RC 方向 / 映射：本地参数草稿注入；
- 电机映射：教学执行机构映射层注入；
- Failsafe：本地安全参数草稿注入；
- 综合案例：组合上述多个教学故障。

即使 PX4 Bridge 在线，**开始案例本身也不会自动写 PX4 参数，也不会自动执行真实电机测试**。

学生在真实 PX4 模式下主动点击“应用参数”时，仍使用现有 PX4 参数写入机制与安全校验。这和自动故障注入是两回事。

## 评分模型

总分 100：

```text
诊断路径       30
故障修复       35
验证闭环       25
操作效率       10
----------------
提示           -8 / 次
失败操作       -3 / 次
```

“诊断路径”依据学生是否进入案例要求检查的模块；“故障修复 / 验证”依据案例成功条件；“操作效率”依据建议时间。

V1 的过程评分用于教学反馈，不应被当作高风险考试防作弊系统。

## 综合案例

F06 不直接告诉学生具体故障答案。学生从“无法完成最终起飞前检查”开始，自主回到对应模块检查。

成功要求包括：

- 遥控方向恢复；
- 遥控验证通过；
- 动力映射恢复；
- M1-M4 单电机验证完成；
- 安全策略冲突消除；
- 安全验证通过；
- 最终起飞前检查通过并生成飞行许可。
